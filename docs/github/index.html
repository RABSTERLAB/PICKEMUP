🕵 Built for investigators, not dashboards-for-the-sake-of-it

Every number on screen is computed from records you collected and can re-verify. Nothing is phoned home, nothing is a black box: verdicts say likely automated, never proof of bot.

Automation scoring, coordination clustering, risk lexicons (Arabic · English · Arabizi), narrative origin tracking and a typed entity index run deterministically, offline. An LLM is an optional narration layer — the product's integrity never depends on it.

How it works

Four stages, one durable pipeline. Every stage is a queue job — atomic claims, retries, dead-letter, all inspectable in the UI.

Collect

  • Bluesky public search — free, no key
  • X API v2 recent search (App-only bearer)
  • BudgetGuard estimates cost before each call; hard per-job & per-day caps
  • Rate-limit aware; errors translated to plain language

Store

  • Posts + accounts with provenance JSON & SHA-256
  • origin_mode: live · fixture · mock · synthetic — badged in the UI
  • Dedup, typed entity index, append-only audit log

Analyze

  • Automation: multi-signal, explainable, ≥2 strong families to flag
  • Coordination: synced reposts, temporal-sync of near-duplicates, popular-artifact exclusion
  • Risk: 6-category AR/EN/Arabizi matrix + operator watchlist
  • Narratives: first-observed origin tracking, honest about gaps

Act

  • Deduped alerts with triage
  • Cases & analyst reports (facts + fingerprint)
  • Optional monitored email delivery, fully audited
A successful collection auto-chains the whole engine pipeline — you never have to remember to run analysis. The monitor then re-analyzes the stored corpus on a schedule and raises alerts on deltas.

Connecting data sources

⚡ Fastest path: Bluesky — nothing to connect. bluesky uses the public app.bsky.app search API: no key, no billing, available the moment you start the app. Choose Bluesky · free in the Overview collect panel, type a query, done. Honest limits: it's a search view of public posts (no firehose, no deleted posts), rate-limited politely with auto-backoff. Everything below applies to the paid X connector.

Connecting X

PICKEMUP reads X through the official API v2 with a single App-only OAuth2 bearer token. It needs only that token — never your password, consumer key or consumer secret. Spend caps ($/job, $/day) are enforced before every HTTP call.

  1. Create the app & get the tokenAt developer.x.com: create a project + app, then copy the Bearer Token (App-only OAuth2). Reading recent search requires a paid access tier with credits — the free tier is write-only.
  2. Give PICKEMUP the tokenEither paste it into Data Sources → X connection → save token (stored locally, masked everywhere, never returned by any API response), or put it in .env as X_BEARER_TOKEN=*** UI value wins over env.
  3. Set your money limitsSame card: max $/job and max $/day (defaults $2 / $10). The BudgetGuard estimates each page pull at ~$0.005/post + $0.010/user-read and refuses calls that would exceed caps — before making them. A live “spent today” counter tracks actuals.
  4. Test, then collectClick test connection — one cheap authenticated call that tells you exactly where you stand. Then on the Overview, type a recent-search query (e.g. (خريجي الجماعة OR caliphate) lang:ar -is:retweet) and press start. Optional intelligence layer (off by default)

Point PICKEMUP at any OpenAI-compatible endpoint (including a fully local model) and two things unlock — without ever weakening the deterministic core:

📝 Narrative reports

The engine still compiles the facts; the model only writes around them. The fact-pack + SHA-256 fingerprint is stored with every report; if the model misbehaves, the template report is produced automatically and the failure is logged.

🔎 Autonomous investigator

An agent over seven read-only tools (risk lists, cluster detail, account dossier, search, entity pivots…) that drafts findings — each cited to stored evidence ids. It cannot collect, delete, or send anything.

Delivery policy: copies to the operator are mandatory and logged; email to authorities is opt-in per report and audited (recipient, time, SHA of content). SMTP + model secrets are write-only, like the X token.

Privacy, honesty & misuse

🔒 Local-first by construction

The database is a file on your disk. The only outbound calls are the Bluesky public API / X API (with your token), an optional LLM endpoint you configure, and optional SMTP. No telemetry, no SaaS, no phoning home.

🏷 Badge what's synthetic

Every record carries an origin mode; demo, mock and fixture data are visibly badged throughout the UI. Synthetic-data metrics are never presented as live-network accuracy.

🗣 Verdicts stay probabilistic

Output language is capped at likely / possible / indeterminate / insufficient evidence. The product never asserts identity, control, or authorship from correlation, and reports organic alternative explanations alongside findings.

⚖ Use it lawfully

Built for researching public coordinated inauthentic behavior — journalism, academia, platform-trust teams, election integrity. Not for harassment, doxxing, or surveilling private individuals. Respect platform ToS and applicable law.

Install & quick start

① Installer (a PC you use)

Run PICKEMUP-Setup-0.1.0.exe (rebuild anytime with scripts\build-installer.bat). Per-user install — no admin rights. A desktop shortcut starts everything; the uninstaller asks before ever touching your collected data. Needs Python ≥ 3.11 (and Node ≥ 18 for the dashboard) on the machine once.

② USB / external drive — nothing installed

Copy the folder to any drive and double-click PICKEMUP_PORTABLE.bat at its root. The venv, node_modules, caches and the SQLite case file all live on the drive — no registry writes, no AppData, no admin. Ports via PICKEMUP_API_PORT / PICKEMUP_WEB_PORT; on a machine without Node it drops cleanly to API-only mode. Same host prerequisites as ①, used read-only.

# ③ Manual / development (any OS): Python ≥ 3.11, Node ≥ 20
git clone https://github.com/<you>/pickemup.git && cd pickemup
scripts/bootstrap.bat                # or: python -m venv .venv && .venv/Scripts/pip install -e ".[dev]"
copy .env.example .env               # optional: X_BEARER_TOKEN + spend caps
scripts\START_PICKEMUP.bat           # one click: API + dashboard + browser
#   (or scripts/dev-all.bat)         # API + worker :8090, dashboard :3000

# verify
.venv/Scripts/python -m pytest tests -q          # 118 tests
.venv/Scripts/python scripts/e2e_demo.py         # full acceptance scenario

Open http://localhost:3000 and collect from Bluesky (free, no setup) immediately — or point the panel at X with a funded token. Flagged posts carry an investigate → action that enrolls them in the human-review queue for extraction and reporting. The labeled offline demo remains available for development (PICKEMUP_DEV_TOOLS=1).
